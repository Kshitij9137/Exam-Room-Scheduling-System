Method
------
The reproducibility service generates the selected data scale twice using the
same seed. It takes a canonical SHA-256 snapshot of rows ordered by primary
key, serializing each row as sorted-key JSON and adding a newline separator.
It also compares per-table row counts. Each temporary generation is rolled
back to its savepoint; existing generated data is not replaced.

Interpretation
--------------
The two observed full-scale runs produced identical row counts and checksums.
The test suite also checks that different seeds produce different checksums.
For the current implementation, this is evidence of deterministic synthetic
master-data generation for the tested seed and environment, not a promise that
every future code version will retain the same checksum.

Constraints
-----------
- Verification refuses to run if append-only ScheduleEvent rows exist. Run it
  before scheduling on a fresh database.
- The report is a recorded observation. Re-run the command to verify the
  current code and environment; the machine-readable output is written to
  data/reproducibility_report.json.
